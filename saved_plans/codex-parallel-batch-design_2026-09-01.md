# Codex parallel-batch retained-evidence design — 2026-09-01

## Authority and exit

This run targets the unchecked Phase 4 exit in
[`codex-parity-plan_2026-08-23.md`](codex-parity-plan_2026-08-23.md): a Codex
parallel batch whose retained evidence lets an independent reviewer recompute
disjoint worktree and state-root identities, exact-head review evidence, and
operator merge authority without merging.

The live-validation contract in
[`live-validation-evidence.md`](../docs/agentic-dev-kit/live-validation-evidence.md)
governs promotion. The retained bundle must pass the repository-owned verifier with
reviewer-supplied authority, source, fixture, runtime, review, redaction, and complete
claim expectations. Narrative, digests without bytes, or a self-consistent manifest
and receipt are not promotion evidence.

assert the current directory before every write sequence, and verify copied or
generated bytes at their destination.

Each task prompt names only its declared note path, forbids the other lane's path,
forbids the cockpit-owned handoff and friction log, requires a ready pull request,
requires `--assert-ready`, and repeats the descriptor's canonical lane contract
through the launcher-owned prompt preamble.

The cockpit must launch the descriptors without changing either lane's branch while
the other is running. Descriptor and terminal receipts must independently report
different canonical worktrees, different canonical state roots, the declared branch,
the same fixture base, and the same review repository.

## Promotion claims

### `codex-parallel-batch-disjoint-identities`

Recompute from both descriptors, launcher observations, filesystem read-back, and
fixture Git read-back that:

- scopes, branches, descriptor ids, worktrees, and state roots match within each
  lane's identity chain;
- worktree paths differ across lanes;
- state-root paths differ across lanes;
- each worktree is linked to the same fixture repository and starts at the declared
  fixture base.

### `codex-parallel-batch-exact-head-review`

Recompute from GitHub pull-request read-back and the scope-local `pr-watch` receipts
that each pull request is open and ready, its head equals the reviewed receipt head,
its head branch matches the persisted lane branch, and the receipt records an
independent review route for that exact head.

### `codex-parallel-batch-operator-authority-without-merge`

Recompute from persisted session metadata, merge-gate refusal captures,
reconciliation output, and final GitHub read-back that each lane is operator-class,
the deterministic merge wrapper refused before a forge mutation, reconciliation
classified the lane as held, and the pull request remained open at final capture.

### `codex-parallel-batch-complete-claim-map`

Recompute that every promoted claim equals the independently supplied expected claim
object, every evidence path exists as retained regular bytes, every artifact digest
matches the captured snapshot, and every retained execution-source byte is proved as
a Git blob member of the named source or fixture revision.

## Required retained artifacts

The bundle will retain:

- client version and source/fixture identity read-backs;
- source and fixture Git commit/tree proofs;
- exact source and fixture bytes for every launcher, session, reconciliation,
  review, configuration, and bundle-verifier dependency used by a promoted claim;
- each descriptor, task prompt, combined-prompt digest, launcher receipt, final
  message, session metadata, activation marker, and sandbox marker;
- filesystem and Git read-back covering both worktrees, state roots, branches, and
  remote heads;
- GitHub repository and pull-request read-back at reviewed and final capture points;
- exact-head review receipts and the commands/results that established them;
- merge-wrapper refusal captures and batch reconciliation output;
- a redaction declaration naming excluded authentication material, credentials,
  tokens, unrelated user data, and unrelated workspace data;
- `bundle.json` and `promotion.json` with the complete expected claim map.

Runtime model, effort, cwd, or session identity is promoted only if the retained
runtime attestation is correlated to the launcher invocation and the claim declares
`requires_applied_compute: true`. Otherwise those observations remain historical and
outside the claim map.

## Hostile controls

Before promotion, operate on disposable copies of the retained directory and require
the verifier to refuse:

- an absent lane receipt;
- an altered descriptor with a restamped manifest digest;
- a claim whose evidence list drops the other lane;
- a review receipt whose head is relabeled away from the GitHub head;
- an operator class changed to self in one retained artifact;
- a source ledger row without its retained source bytes;
- a credential-like key or assignment introduced into a retained artifact;
- a promotion receipt checked without independent expected bindings.

The positive bundle is verified again after every hostile copy is discarded. The
hostile copies never replace retained positive-control bytes.
