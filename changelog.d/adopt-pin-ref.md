## Pass a ref when you adopt the kit

`adopt.md` Step 0 now clones the kit at a ref you name: set `KIT_REF` to a release tag or a full commit sha before running the kit block, and the block prints the resolved commit (`kit commit: <sha>`) before the first copy. Put that sha in the adoption's pull request. With no `KIT_REF` the block uses `main`, as it stands when it runs. A ref that starts with `-` is refused before any git call, and a full sha is lower-cased. When the block finds a clone an earlier run made, it checks a named ref against the clone's `HEAD` without fetching into it, and with `main` its `kit commit:` line says the found clone was not re-checked. The steps after it run the named ref's own engines, so name a ref no older than the `adopt.md` you follow. Upgrades still read the kit's `main` only: pinning an upgrade is tracked in #1445.
