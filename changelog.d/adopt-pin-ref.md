## Pass a ref when you adopt the kit

`adopt.md` Step 0 now clones the kit at a ref you name: set `KIT_REF` to a full commit sha, a tag or a branch before running the kit block, and the block prints the resolved commit (`kit commit: <sha>`) before the first copy. Put that sha in the adoption's pull request: a full sha is the only pin that cannot move, since a tag can be moved like a branch, and the printed line records what was installed. Set `KIT_REF=''` explicitly in the invocation that runs the block to select the remote's default branch. An unset choice stops the block before cloning (see `adopt-retain-kit-pin.md`). A ref that starts with `-` is refused before any git call, and a full sha is lower-cased. When the block finds a clone an earlier run made, it checks a named ref against the clone's `HEAD` without changing the clone, and with no ref named its `kit commit:` line says the found clone was not re-checked. The steps after it run the named ref's own engines, so name a ref no older than the `adopt.md` you follow. For an upgrade, follow the ref selection and installed-revision check in `upgrade-pin-ancestry.md`.
