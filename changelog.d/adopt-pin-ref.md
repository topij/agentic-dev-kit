## Pass a ref when you adopt the kit

`adopt.md` Step 0 now clones the kit at a ref you name: set `KIT_REF` to a full commit sha, a tag or a branch before running the kit block, and the block prints the resolved commit (`kit commit: <sha>`) before the first copy. Put that sha in the adoption's pull request: a full sha is the only pin that cannot move, since a tag can be moved like a branch, and the printed line records what was installed. With `KIT_REF` unset or empty the block clones the remote's default branch, as it stands when it runs, as before. A ref that starts with `-` is refused before any git call, and a full sha is lower-cased. When the block finds a clone an earlier run made, it checks a named ref against the clone's `HEAD` without changing the clone, and with no ref named its `kit commit:` line says the found clone was not re-checked. The steps after it run the named ref's own engines, so name a ref no older than the `adopt.md` you follow. Upgrades still read the remote's default branch only: pinning an upgrade is tracked in #1445.
